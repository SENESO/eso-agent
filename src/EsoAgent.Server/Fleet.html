ACL rules

        
One rule per line: from -> to [ports] — from/to are device codes or group:name; ports comma-separated, empty = all. Default posture: fleet members can reach each other's agent port (8737); everything else is denied at the device firewall.

        
        

        

      
Mesh exit node

        
One device can be the fleet's exit node: devices that opt in (agent config mesh.useExitNode) route all their traffic through it. The exit node forwards + NATs on Linux; on Windows, NAT is a manual step (see USER-GUIDE).

        

        

        

      
Enrollment keys

        
Pre-approval keys for unattended installs. A device presenting a valid key at enrollment is approved automatically. The key is shown ONCE at creation; only its hash is stored.

Operator access
…

        
Owner-reserved. Revoking cuts the operator's access everywhere: the server refuses its calls and every approved device drops its key. You keep full control from this panel.

        

      
Rotate operator key

        
Owner-reserved. Paste the NEW operator public key (from eso keygen). Devices are told to trust the new key and drop the old one; the old key dies on the server immediately.

        
        

        

      
Owner password

        
Owner-reserved: only you, here, can change it.

Alert webhook

        
Alerts (offline devices, low disk, failed logins…) are also POSTed as signed JSON to this URL. Header X-Eso-Signature = HMAC-SHA256 of the body with the secret (shown once when first generated).

        

        

        

      
Access codes (hand a device to someone)

        
Mint a short code for ONE device. Whoever holds it redeems it for a signed, scoped, expiring grant — no account, no password sharing. Grants never include owner powers. The code is shown ONCE.
